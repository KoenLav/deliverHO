Requests run through real screening. Pressing request calls screen() — operator vergunning, gemeente rules, client verification, worker eligibility, published availability and boundaries. Try requesting Noor: a blocking risk signal stops it, from the real detector.
No face photos by default. A photo used elsewhere links identities through reverse image search, the most common way workers get outed. An initial unless the worker chooses otherwise, never framed as incomplete.
One named person, not a broadcast. Workers are never put in silent competition. Unanswered requests expire rather than passing on.
No ratings anywhere. Public rating of a person's sexual services is a pressure mechanism with no upside to them.

No names, no addresses, no client. The worker column is a real HMAC-SHA256 pseudonym computed in your browser, keyed outside the database, so a database breach re-identifies nobody. Enough to show a gemeente that licensed work happened; not enough to out anyone.
What is real: the booking state machine, screening gates, eligibility checks, safety sessions, escalation sweep, coercion detectors and administration records are the production modules, bundled unchanged. What is not: the screens, the people, the vergunning, and the server — there is no database and no authentication here, and the safety clock is compressed so a booking takes a minute instead of an hour.
